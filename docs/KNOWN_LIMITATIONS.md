## ۵. محدودیت‌های آگاهانهٔ دامنه (توضیح‌داده‌شده، نه نقص)

1. **همهٔ اعداد تجربی فرضیه‌اند.** حاشیهٔ ۲۰٪، سقف جبرانی ۳۰٪، آستانه‌های تسلط، ضرایب اولویت و بازه‌های مرور از مطالعهٔ این کاربر مشتق شده‌اند، نه از قانون علمی. همه در `config.py` با برچسب `[H]` و در تنظیمات قابل تغییرند.
2. **تاریخ رسمی آزمون حدس زده نمی‌شود.** نمونهٔ «۳۰ مهر» سال ندارد و سالی برایش ساخته نمی‌شود؛ وضعیت تاریخ (رسمی/تخمینی/نامشخص) کاربر تعیین می‌کند.
3. **پایگاه دادهٔ شروع خالی است، ولی wizard دادهٔ شروع را از کاربر می‌گیرد.** در نصب تازه هیچ کلاس، روال، فعالیت، کتابِ ازپیش‌انتخاب‌شده، آزمون یا آمار نمونه‌ای seed نمی‌شود؛ wizard رشته و درس/کتاب و در صورت انتخاب کاربر کلاس‌ها، تعهدها و روال‌ها را ثبت می‌کند. رویدادهای تعارض نیز فقط از داده‌هایی ساخته می‌شوند که کاربر واقعاً ثبت کرده است (D-023).
4. **رکوردهای واقعی پایگاه دادهٔ موجود کاربر خودکار پاک نمی‌شوند.** فقط bundle کامل و دست‌نخوردهٔ برنامهٔ قدیمی، با marker معتبر و بدون تغییر/استثنا، پاک می‌شود؛ در غیر این صورت schedule حفظ می‌شود. دو فیلد متنی راه‌اندازی که فقط از seed/پرسش ساختگی ساخته می‌شدند کنار گذاشته می‌شوند.
5. **هیچ تشخیص پزشکی/روان‌شناختی** — نشانگر «فشار برنامه» فقط رفتار سیستم را توصیف می‌کند.
6. **بدون چت‌بات آزاد، استریک یا رتبه‌بندی** (NFR-01، NFR-02).
7. **هفتهٔ شنبه‌محور** — اگر کاربر هفتهٔ دیگری بخواهد، باید در `jdate.weekday_index` تغییر کند.

## ۶. مخزن و انتشار بسته

مخزن عمومی پروژه `rezaa2544/k2` و شاخهٔ اصلی upstream `main` گزارش شده است. فایل `downloads/K2-windows-x64.zip` در این workspace artifact کامل one-folder نسخهٔ قبلی است و با `K2.exe` و پوشهٔ `_internal` یکجا نگه‌داری می‌شود. این checkout در نوبت 2026-10-17، Git remote قابل‌استفاده نمایش نداد و push انجام نشد؛ بنابراین artifact و CI پیشین را نباید به کد جاری نسبت داد.

در صورت push روی `main`، گردش‌کارهای تعریف‌شده باید تست‌ها را اجرا کنند؛ در صورت تغییر هر فایلی زیر `src/`، CI الزام می‌کند `preview/K2-preview.html` هم در همان تغییر به‌روز شود. Windows CI، EXE را می‌سازد و headless اجرا می‌کند و فقط پس از موفقیت می‌تواند ZIP کامل را همگام کند. این‌ها رفتار تعریف‌شدهٔ workflow هستند، نه نتیجهٔ اجرای این تغییرها: در این checkout remote وجود ندارد، workflow تازه اجرا نشده و push انجام نشده است. انتشار در GitHub Releases جداست و با tag نسخه (`v*`) به‌صورت draft ساخته می‌شود.

برای تغییرات بعدی، ابتدا تست‌ها را اجرا کنید، سپس commit و push معمولی انجام دهید:

```bash
cd /home/user/k2
PYTHONPATH=src QT_QPA_PLATFORM=offscreen python -m pytest tests -q
git status --short
git add <files>
git commit -m "<message>"
git push origin main
```

برای بررسی نتیجه، در GitHub Actions باید run مربوط به commit را بازبینی کرد؛ لینک دانلود مستقیم پس از موفقیت build به ZIP تازهٔ مخزن اشاره می‌کند. هیچ force-push یا بازنویسی تاریخچه‌ای لازم نیست؛ فایل ZIP کامل نیز نباید با EXE تنها جایگزین شود.
