# مرحله ۲ — موتور برنامه‌ریزی، ظرفیت، مهلت‌ها و مدیریت عقب‌افتادگی

> تاریخ تهیه: ۲۴ مهر ۱۴۰۵
> برچسب‌ها مثل مرحله ۱: **[K]** از دانش من و نیازمند راستی‌آزمایی، **[H]** فرضیه محصول و قابل تنظیم.

## ۱. اصول

1. **ظرفیت هر روز محاسبه می‌شود، نه ثابت فرض می‌شود.** ساعت مطالعه خروجی است نه ورودی.
2. **برنامه همیشه کمتر از ظرفیت پر می‌شود** تا برای اتفاق پیش‌بینی‌نشده جا بماند. ریشه علمی: مغالطه برنامه‌ریزی (Buehler, Griffin & Ross 1994) — مردم زمان لازم برای کارها را کم‌برآورد می‌کنند [K؛ شواهد قوی].
3. **سیستم تصمیم‌های کم‌اهمیت را خودش می‌گیرد، تصمیم‌های ارزشی را به کاربر می‌سپارد.** مثلاً «کدام فعالیت را حذف کنم» پیشنهاد می‌شود ولی بدون تأیید اجرا نمی‌شود.
4. **ساده‌ترین الگوریتمی که کار می‌کند** (قاعده‌محور + امتیازدهی)، نه حل‌کننده سنگین.

## ۲. مدل ظرفیت روزانه

```
بازه_بیداری      = ساعت بیداری تا ساعت خواب (خواب = محدودیت سخت)
ثابت             = کلاس‌ها + رفت‌وآمد + آزمون + تعهدات تأییدشده
ضروری            = غذا + استراحت + حمام/بهداشت + نماز/خانواده (قابل ثبت)
خام              = بازه_بیداری - ثابت - ضروری
مؤثر             = خام × ضریب_تمرکز × ضریب_انرژی
ظرفیت_برنامه     = مؤثر × (1 - حاشیه_اطمینان)        // پیش‌فرض حاشیه ۲۰٪ [H]
```

- **ضریب تمرکز**: نسبت «دقیقه عمیق واقعی» به «دقیقه در نظر گرفته‌شده»، از تاریخچه کاربر (میانه ۱۴ روز گذشته). شروع با ۰٫۶ [H]؛ با داده اصلاح می‌شود.
- **ضریب انرژی**: خودگزارشی ۱ تا ۳ (کم/متوسط/خوب) هر صبح. ۱ → ۰٫۶، ۲ → ۰٫۸، ۳ → ۱٫۰ [H]. بدون هیچ تشخیص پزشکی؛ فقط ثبت.
- **روز کلاس سنگین**: ظرفیت خودکار از کلاس‌ها کم می‌شود؛ بخش پس از کلاس با ضریب افت‌شده (قابل تنظیم) محاسبه می‌شود.
- **بلوک‌های مطالعه**: هر روز به بلوک‌های ۳۰ تا ۹۰ دقیقه‌ای تقسیم می‌شود (اندازه قابل تنظیم). فعالیت دشوار در ساعات «پربازده» کاربر قرار می‌گیرد؛ ساعات پربازده از داده خود کاربر (دقت تست‌ها در ساعت‌های مختلف) یاد گرفته می‌شود، نه از ادعای عمومی.

**نمایش به کاربر:** «ظرفیت امروز ۳:۲۰، برنامه ۲:۵۰، حاشیه ۳۰ دقیقه».

---

## ۳. تخمین زمان فعالیت

- کاربر برآورد می‌دهد (`est`).
- سیستم نسبت `actual/est` برای هر **نوع فعالیت** (کلاس ضبط‌شده، تست، تحلیل، ...) ثبت می‌کند.
- پیش‌بینی برنامه‌ریزی = `est × صدک ۷۰ نسبت‌های گذشته` (حداقل ۵ نمونه، وگرنه ۱٫۳ [H]).
- نمایش اختلاف تخمین و واقعیت به‌عنوان بازخورد آموزشی («معمولاً ۳۰٪ بیشتر طول می‌کشد»).

## ۴. وظایف: مدل داده

```
Activity {
  id, title, type, subject, topic_id
  est_minutes, actual_minutes, remaining_minutes
  min_chunk, max_chunk, splittable
  deadline_type        // HARD | SOFT | NONE
  deadline_at
  depends_on[]         // وابستگی‌ها
  blocks[]             // چه چیزی را مسدود می‌کند
  priority_base        // پایه از نوع
  state, state_reason
  created_at, first_planned_at, times_rescheduled
  energy_need          // HIGH | MED | LOW
}
```

انواع فعالیت: کلاس ضبط‌شده، تکلیف، مطالعه/پردازش، تست آموزشی، تست زمان‌دار، تحلیل تست، تثبیت، رفع اشکال، حل مجدد، مرور سررسید، آزمون (ثابت)، جمع‌بندی.

## ۵. ماشین حالت

```
Planned ──► Ready ──► InProgress ──► Done
   │          │          │  ▲
   │          │          ▼  │
   │          │        Partial ──► (remaining_minutes > 0 → Ready)
   │          ▼
   │       Blocked  (منتظر وابستگی)
   ▼
Overdue ──► Ready (بازبرنامه‌ریزی)
   │
   ├─► Deferred   (کاربر آگاهانه به بعد موکول کرد؛ دلیل)
   ├─► Expired    (ارزش از بین رفت؛ مثلاً آزمونی که گذشته)
   └─► Dropped    (کاربر حذف کرد؛ دلیل ثبت می‌شود)
```

**قواعد گذار:**
- `Planned → Ready` وقتی همه `depends_on` در حالت Done باشند.
- `InProgress → Partial` اگر زمان واقعی < ۸۰٪ برآورد [H] و کاربر «تمام شد» نزند.
- `Overdue` وقتی `deadline_at` گذشته و Done نشده.
- `Expired` به‌صورت خودکار پیشنهاد می‌شود، **نه** اجرا: «این تحلیل آزمون جدید دیگر قابل استفاده نیست؛ منقضی شود؟».
- ثبت دلیل برای Deferred/Dropped/Overdue: انتخاب سریع از فهرست (کم‌انرژی، کلاس ثبت‌نشده، بیش از حد زیاد، سؤال، دلیل دیگر). این داده بازخورد برای تنظیم ظرفیت می‌شود.

## ۶. مهلت واقعی و وابستگی

| سناریو | قاعده |
|---|---|
| کلاس ضبط‌شده یکشنبه (شیمی/دینی) | مهلت = شروع جلسه بعدی همان درس − ۱ روز حاشیه |
| کلاس آفلاین زمین‌شناسی دوشنبه | مهلت = شروع جلسه بعدی زمین‌شناسی − حاشیه؛ **مدت = طول ویدیو × ۱٫۲** |
| آزمون مستقل هر درس قبل از جلسه بعدی | وابستگی: «مرور مبحث» و «تست آموزشی» پیش از آزمون، مهلت = ۱ روز قبل آزمون |
| آزمون جامع دوهفتگی پنجشنبه | HARD؛ هفته قبل: مرور حیاتی؛ شب قبل: سبک (بدون مطلب جدید سنگین) |
| تکلیف جلسه | وابسته به کلاس مربوط؛ مهلت = جلسه بعدی |
| رفع اشکال/حل مجدد | مهلت نرم: ≤۷۲ ساعت بعد از آزمون |

نکته: **حضور در کلاس ≠ یادگیری.** فعالیت «پردازش اولیه» (مرحله ۴ در مرحله ۱) به‌صورت وابسته به کلاس ایجاد می‌شود و بدون آن، فعالیت «تمرین» در حالت Blocked می‌ماند.

## ۷. امتیاز اولویت

```
score(a) =  w1 × فوریت_مهلت(a)
          + w2 × تعداد_وابسته‌های_مسدودشده(a)
          + w3 × وزن_مبحث × ضعف_مبحث
          + w4 × سررسید_مرور(a)
          + w5 × سن_عقب‌افتادگی(a)
          − w6 × هزینه_زمان(a)

فوریت_مهلت = 1 / max(0.5, روز_تا_مهلت)    // HARD ضریب ۳ [H]
```

وزن‌های پیش‌فرض (قابل تنظیم و کالیبره با داده): `w1=3, w2=2, w3=2, w4=2, w5=1, w6=0.5` [H].

**چرا ضعف × وزن؟** تا وقت محدود روی چیزی صرف شود که هم ضعیف است هم در آزمون مهم. وزن مبحث از تنظیمات آزمون هدف (سال/گروه/درس) می‌آید و **نباید** ثابت کدگذاری شود.

## ۸. محدودیت‌ها

**سخت (هرگز نقض نمی‌شوند):**
1. عدم هم‌پوشانی فعالیت‌ها.
2. کلاس‌ها و آزمون‌های تأییدشده.
3. پنجره خواب و فعالیت‌های ضروری.
4. ظرفیت روزانه (بدون اضافه‌کاری خودکار).
5. وابستگی‌های اجباری (Blocked تا آماده).

**نرم (با هزینه جریمه قابل نقض):**
1. رعایت مهلت‌های نرم.
2. حداقل و حداکثر اندازه بلوک.
3. تقسیم‌ناپذیری فعالیت (اگر قابل تقسیم نیست در یک بلوک بنشیند).
4. هماهنگی دشواری با ساعت پربازده.
5. حداقل جابه‌جایی نسبت به برنامه فعلی (ثبات).
6. توزیع متعادل درس‌ها (اجتناب از یک درس در تمام روز).
7. سقف کار جبرانی روزانه.

## ۹. مقایسه رویکردها

| رویکرد | مزیت | عیب | توصیه |
|---|---|---|---|
| **Rule-Based + امتیازدهی** | ساده، قابل توضیح، سریع، آفلاین | بهینه سراسری نیست | **نسخه ۱** |
| **Constraint Programming** (مثلاً OR-Tools CP-SAT) [K] | بهینه‌سازی دقیق | پیچیدگی، وابستگی، توضیح‌پذیری ضعیف | نسخه ۲ (اختیاری) برای هفته |
| بهینه‌سازی عددی/Heuristic (SA، ژنتیک) | انعطاف | تنظیم سخت، رفتار غیرقابل پیش‌بینی | توصیه نمی‌شود |

**نسخه ۱ پیشنهادی (قدم‌به‌قدم):**
1. بلوک‌های آزاد هر روز را بسازد (ظرفیت بخش ۲).
2. فعالیت‌های Ready را بر اساس `score` مرتب کند.
3. برای هر فعالیت، اولین بلوک مناسب را بر اساس `energy_need` و مهلت بیابد (برای HARD از عقب به جلو: «آخرین زمان ممکن − حاشیه»).
4. اگر جا نبود: تقسیم (اگر مجاز) یا ثبت در «فهرست جای‌نگرفته» و فعال‌شدن هشدار بخش ۱۱.
5. بازبینی محلی: تعویض‌های کوچک برای کاهش جریمه نرم.
6. نمایش **دلیل** هر جایگذاری («چون مهلت ۲ روز دیگر است»).

## ۱۰. بازبرنامه‌ریزی

| محرک | واکنش |
|---|---|
| پایان روز | فعالیت‌های ناتمام به Partial/Overdue؛ بازتوزیع روزهای آتی |
| کلاس لغو شد | بلوک آزاد می‌شود؛ پیشنهاد استفاده (مرور سررسید یا عقب‌افتاده) |
| روز بیماری/کم‌انرژی | فعال‌سازی **برنامه حداقلی** (بخش ۱۲)؛ بدون جریمه |
| کار فوری | کاربر زمان را مسدود می‌کند؛ سیستم باقی را بازچینی می‌کند |
| آزمون زودتر/دیرتر | محاسبه مجدد مهلت‌ها و سقف مرور |

**ثبات برنامه:** تغییر برنامه نباید بیش از N=۲ بار در روز بدون درخواست کاربر رخ دهد [H]؛ بازبرنامه‌ریزی مکرر خودش یک منبع فرسودگی است.

## ۱۱. مدیریت عقب‌افتادگی

### ۱۱.۱ مفهوم‌ها

- **بدهی عقب‌افتادگی** = مجموع `remaining_minutes` فعالیت‌های Overdue.
- **سن** = روز از مهلت.
- **نسبت بدهی** = بدهی ÷ ظرفیت قابل جبران در ۷ روز آینده.

### ۱۱.۲ سطح‌بندی

| سطح | شرط (پیش‌فرض [H]) | واکنش |
|---|---|---|
| سبز | نسبت بدهی < ۰٫۳ | عادی |
| زرد | ۰٫۳ ≤ نسبت < ۰٫۷ | هشدار + پیشنهاد کاهش اختیاری |
| نارنجی | ۰٫۷ ≤ نسبت < ۱ | صف جبران فعال؛ مرور سبک؛ تأیید حذف اختیاری‌ها |
| قرمز | نسبت ≥ ۱ | **بازتنظیم هفته:** فهرست سه‌بخشی (حتماً/اگر شد/رها) برای تأیید |

### ۱۱.۳ سقف جبرانی

سقف کار جبرانی روزانه = ۳۰٪ ظرفیت (پیش‌فرض) [H]. هدف: جلوگیری از اینکه روز به «روز تلافی» تبدیل شود و کار اصلی عقب بیفتد. اگر کاربر بخواهد، قابل تغییر است.

### ۱۱.۴ اولویت جبران

۱. فعالیت‌هایی که جلسه/آزمون بعدی را مسدود می‌کنند.
۲. مرورهای سررسیدشده برای موارد ضعیف.
۳. رفع اشکال آزمون اخیر.
۴. تکلیف‌های بدون مهلت سخت.
۵. فعالیت‌هایی که ارزش آن‌ها کم شده (پیشنهاد Expired/Dropped).

### ۱۱.۵ قابل تقسیم بودن و ناقص بودن

- تقسیم‌پذیر: ویدیوی ضبط‌شده (با علامت نقطه توقف)، تست‌زنی، مرور.
- تقسیم‌ناپذیر: آزمون زمان‌دار، شبیه‌سازی.
- فعالیت **ناقص** اگر `0 < actual < est` و کاربر تأیید «پایان» نکرده است؛ باقیمانده = `max(est×کالیبراسیون − actual, حداقل ۱۰ دقیقه)`.

### ۱۱.۶ پیشگیری

- تعیین مهلت برای هر فعالیت در لحظه ایجاد.
- هشدار پیش از پر شدن ظرفیت هفته، نه پس از آن.
- «ظرفیت پیش‌بینی‌نشده» در برنامه وجود دارد (حاشیه ۲۰٪).
- مرور هفتگی ۱۵ دقیقه‌ای: اتمام/ناتمام/حذف.

### ۱۱.۷ بازگشت پس از وقفه چندروزه

1. **عدم تنبیه:** گزارش «بدهی» به‌صورت خنثی؛ بدون عبارت سرزنش‌آمیز.
2. **روز اول:** بار ۴۰٪ [H] + آزمون کوتاه سنجش ماندگاری مطالب مهم.
3. **۳ تا ۵ روز:** افزایش تدریجی.
4. **بازتنظیم مهلت‌ها:** فعالیت‌هایی که دیگر معنی ندارند (کلاسی که ۲ جلسه از آن گذشته) به Expired پیشنهاد می‌شوند.
5. **صف مرور** با روش بخش ۳.۶ مرحله ۱ فشرده می‌شود.

## ۱۲. برنامه حداقلی روزهای دشوار

محتوای پیش‌فرض (حدود ۲۵ تا ۴۰٪ ظرفیت معمول [H]):
1. مرور سررسیدِ سطح «حیاتی».
2. یک فعالیت کوتاه و آسان (حفظی یا تست کوتاه).
3. اگر مهلت HARD در ۲۴ ساعت آینده: فقط آن.
4. بدون مطلب جدید سنگین.

انتخاب «روز حداقلی» بدون جریمه است؛ در آمار به‌عنوان «روز حداقلی» ثبت می‌شود نه «روز شکست».

---

## ۱۳. خواب و سلامت برنامه

- خواب «محدودیت سخت» است؛ سیستم هیچ فعالیتی را در پنجره خواب نمی‌گذارد.
- **جلوگیری از برنامه‌ریزی شبانه غیرواقعی:** سقف ساعت آخر مطالعه (ثابت کاربر)، نه حذف خودکار؛ هشدار اگر برنامه از آن عبور کند.
- نشانگر فشار بیش‌ازحد (بدون تشخیص پزشکی): ترکیب (۱) کاهش ضریب انرژی ≥ ۳ روز، (۲) افزایش نسبت بدهی، (۳) ثبت دلایل «خیلی زیاد» ≥ ۳ بار در هفته. اقدام: پیشنهاد کاهش حجم + پیام «اگر این وضعیت ادامه دارد، با مشاور یا فرد مورد اعتماد صحبت کن». نرم‌افزار درمانگر نیست و تشخیص نمی‌دهد.
- مرزبندی «کارهای روزمره» از «مطالعه»: برچسب دسته در تقویم؛ هیچ‌کدام در ساعات مطالعه محسوب نمی‌شوند.

## ۱۴. معیارهای سنجش موتور

| شاخص | تعریف | هدف [H] |
|---|---|---|
| نرخ تحقق برنامه | فعالیت‌های Done ÷ برنامه‌ریزی‌شده | ≥ ۷۰٪ بدون کاهش کیفیت |
| خطای تخمین | میانه |actual − predicted| ÷ actual | کاهش با زمان |
| نرخ بازبرنامه‌ریزی | تعداد تغییرات برنامه در روز | ≤ ۲ |
| نسبت بدهی هفتگی | بخش ۱۱.۱ | < ۰٫۳ در بیشتر هفته‌ها |
| رعایت HARD | تعداد مهلت‌های HARD از دست رفته | ۰ |

## ۱۵. نقاط تصمیم: سیستم یا کاربر

| تصمیم | که تصمیم می‌گیرد |
|---|---|
| جای‌گذاری فعالیت در بلوک | سیستم |
| تقسیم فعالیت قابل تقسیم | سیستم |
| ترتیب جبران | سیستم (قابل تغییر) |
| حذف/موکول فعالیت | **کاربر** |
| کاهش حجم هدف | **کاربر** (با پیشنهاد) |
| تغییر تاریخ/مهلت آزمون | **کاربر** |
| فعال‌سازی روز حداقلی | **کاربر** (پیشنهاد خودکار هنگام انرژی ۱) |
