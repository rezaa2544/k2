## ۵. قواعد کیفیت اجرایی

1. هیچ تستی حذف، skip یا ضعیف نمی‌شود. اگر انتظار تست اشتباه بود، **انتظار** اصلاح می‌شود و دلیلش در تاریخچهٔ commit می‌آید.
2. هر commit کوچک و معنادار است و پیامش به‌فارسی و با ذکر دلیل نوشته می‌شود.
3. `.gitignore` مانع commit شدن پایگاه دادهٔ کاربر، پشتیبان و خروجی بسته‌بندی است.
4. هیچ توکن، کلید یا اطلاعات شخصی در کد، لاگ، commit یا مستندات قرار نمی‌گیرد.
5. دستورهای اجرا و تست در README و `TEST_STRATEGY.md` **دقیقاً** همان چیزی هستند که اجرا شده‌اند.
6. گزارش هر مرحله شامل: فایل‌های تغییرکرده، شناسهٔ نیازمندی‌های تکمیل‌شده، فرمان دقیق تست و خروجی آن، تست‌های اجرا نشده + دلیل، محدودیت‌ها، شاخه/HEAD و وضعیت push.
