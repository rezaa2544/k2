# راهنمای رابط و تجربهٔ کاربری K2

نسخه: ۱.۰ · آخرین بازبینی: ۱۴۰۵/۰۷/۲۵ (۲۰۲۶/۱۰/۱۷)

## هدف طراحی

K2 ابزارِ همراهِ یک دانش‌آموز است، نه داشبوردِ رقابتی یا تابلوی هشدار. رابط باید در چند ثانیه به سه پرسش پاسخ دهد: «امروز چه ظرفیتی دارم؟»، «قدم بعدی چیست؟» و «آیا چیزی نیاز به تصمیم من دارد؟». وضوح و آرامش بر تزئینات و انباشت شاخص‌ها مقدم است.

## نظام بصری

| توکن | مقدار | کاربرد |
|---|---|---|
| پس‌زمینه | `#F3F6F8` | سطح اصلی و کم‌خستگی |
| سطح کارت | `#FFFFFF` | تفکیک اطلاعات بدون خطوط سنگین |
| سبز اصلی | `#176B55` | اقدام اصلی، ظرفیت، نشانهٔ پیشرفت |
| سبز تیره | `#102D2A` | نوار ناوبری؛ جداسازی روشنِ ساختار از محتوا |
| آبی اطلاعاتی | `#385F88` | اطلاعات/شاخص خنثی |
| کهربایی | `#87641B` | مورد نیازمند توجه یا پرسش حل‌نشده |
| قرمز آرام | `#8A4848` | فقط خطا یا وضعیت واقعاً پرخطر |
| متن اصلی / ثانویه | `#182B2A` / `#687B7A` | سلسله‌مراتب خواندن |

فونت همراه برنامه Vazirmatn است. ارقام و تاریخ در UI شمسی‌اند؛ ذخیره‌سازی داخلی مستقل از ظاهر و تقویم می‌ماند. گوشه‌های نرم، مرزهای نازک، فاصلهٔ قابل‌تنفس و یک اقدام اصلی در هر بخش، زبان مشترک اجزاست.

## الگوی صفحه‌ها

- **ستون کناری ثابت:** نشان K2، ناوبری نام‌دار، زیرنویس کوتاه و یادآوری آفلاین/خصوصی. حالت انتخاب‌شده با رنگ و نشان مرزی مشخص می‌شود؛ تنها به رنگ متکی نیست.
- **نوار بالای محتوا:** عنوان صفحه، توضیح یک‌خطی، تاریخ شمسی و تازه‌سازی.
- **داشبورد:** خلاصهٔ روز ← پیشنهاد مشاور و دو اقدام ← چهار شاخص ← توضیح ظرفیت و زمینهٔ آزمون/بدهی ← پرسش‌های حل‌نشده.
- **فرم و جدول:** برچسب صریح، توضیح ورودی، وضعیت تمرکز، انتخاب خوانا، و جای کافی برای متن فارسی.
- **هشدار:** متن می‌گوید چه چیزی نامعلوم است، چرا تصمیم کاربر لازم است و قدم بعد چیست؛ فعالیت حل‌نشده حذف یا قطعی فرض نمی‌شود.

## اصول تعامل

1. یک مسیر اصلی روشن، مسیر جایگزین کم‌فشار و برچسب‌های کوتاه ارائه شود؛ واژه‌های فنی به متن کمکی منتقل شوند.
2. وضعیت خالی باید با پیشنهاد بعدی همراه باشد، نه نمودارِ صفر یا بن‌بست.
3. هیچ رنگ/متنی نباید «بدهی» را به شکست شخصی تبدیل کند؛ روز حداقلی و حفظ خواب همیشه دسترس‌پذیر است.
4. انتخاب کاربر و دادهٔ واردشده بر پیش‌فرض‌های قابل‌تغییر غلبه دارد؛ تاریخ/قانون آزمون بدون منبع رسمی قطعی نشان داده نمی‌شود.
5. همهٔ عملیات اصلی با موس و صفحه‌کلید و متن فارسی قابل‌دسترسی‌اند؛ پیام‌های خطا باید توضیحی و قابل‌بازیابی باشند.

## پیاده‌سازی و اعتبارسنجی

تم در `src/k2/ui/theme.py`، پنجره/ناوبری در `src/k2/ui/app.py`، کارت‌ها در `src/k2/ui/widgets.py` و داشبورد در `src/k2/ui/views/dashboard.py` پیاده‌سازی شده است. منطق محصول در لایهٔ UI تکرار نشده و ظاهر نباید رفتار زمان‌بند یا محدودیت‌های خواب/ظرفیت را تغییر دهد.

- تست‌های GUI و کل مجموعه: `PYTHONPATH=src QT_QPA_PLATFORM=offscreen python3 -m pytest tests -q`.
- پیش‌نمایش واقعی رابط از اجرای EXE ویندوزی زیر Wine + Xvfb در `images/k2-dashboard.png` نگهداری می‌شود.
- وضعیت دسترس‌پذیری که نیازمند آزمون با صفحه‌خوان، بزرگ‌نمایی سیستم و کاربران واقعی است هنوز **تأیید میدانی نشده**؛ فهرست کامل محدودیت‌ها در `KNOWN_LIMITATIONS.md` است.

## مرزبندی طراحی

در این نسخه عمداً از نمودارهای پرتراکم، استریک، مقایسهٔ همسالان، تصویرسازی تزئینیِ سنگین، چت‌بات آزاد و اعلان‌های مداخله‌گر استفاده نشده است. این تصمیم‌ها برای کاهش حواس‌پرتی و حفظ خودمختاری دانش‌آموز هستند، نه محدودیت فنی.
