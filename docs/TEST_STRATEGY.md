# راهبرد تست — K2

نسخهٔ سند: 1.0 — آخرین به‌روزرسانی: ۱۴۰۵/۰۷/۲۴ (2026-10-17)

---

## ۱. اصول

1. **تست، جایگزین حدس نیست.** هر ادعای محصول باید به یک تست قابل اجرا وصل باشد.
2. **تست ضعیف نشود.** اگر تستی شکست خورد، یا کد اصلاح می‌شود یا **دلیل** صریحاً مستند می‌شود (نه اینکه assertion را بی‌صدا حذف کنیم). تاریخچهٔ commitها این را نشان می‌دهد: چند مورد با تغییر انتظارات تست (که اشتباه بودند) اصلاح شد، نه با حذف تست.
3. **Build ≠ Run.** ساخت EXE بدون اجرای آن، تأیید محسوب نمی‌شود (D-013).
4. **مرزهای واقعی.** تست‌ها روی داده‌های مصنوعی ولی دقیق (ظرفیت‌ها، تاریخ‌ها و مهلت‌های واقعی) اجرا می‌شوند.
5. **تکرارپذیری.** هیچ تستی به زمان واقعیِ سیستم، شبکه، یا فایل‌های خارج از `tmp_path` وابسته نیست.

## ۲. دستورهای اجرا

```bash
# همهٔ تست‌ها
export PYTHONPATH="$PWD/src"
export QT_QPA_PLATFORM=offscreen
python -m pytest tests -q

# فقط تست‌های رابط کاربری
python -m pytest tests -m gui -q

# با گزارش خطای کامل
python -m pytest tests -vv --tb=long

# گزارش XML برای CI
python -m pytest tests --junitxml=pytest-report.xml
```

`QT_QPA_PLATFORM=offscreen` در `tests/conftest.py` پیش از واردکردن PySide6 تنظیم می‌شود، بنابراین اجرای تست‌ها روی CI بدون نمایشگر ممکن است.

## ۴. دستهٔ خاصیت‌ها (Invariant) و مرزها

`test_invariants.py` با داده‌های شبه‌تصادفی (seed ثابت) روی یک هفتهٔ کامل بررسی می‌کند:

* **I-1:** هیچ دو جای‌گذاری هم‌پوشانی ندارند.
* **I-2:** هیچ جای‌گذاری داخل بازهٔ خواب/کلاس/تعهد نیست.
* **I-3:** مجموع زمان برنامه‌ریزی‌شده از ظرفیت مؤثر بیشتر نمی‌شود.
* **I-4:** هر فعالیت در طول هفته یا جا گرفته یا صریحاً «جای‌نگرفته» گزارش شده است.
* **I-5:** فعالیت با مهلت سخت، زودتر از فعالیت بدون مهلت اولویت می‌گیرد.

`test_edge_cases.py` حالت‌هایی را می‌پوشد که معمولاً در محصول واقعی رخ می‌دهند اما در تست‌های عادی گم می‌شوند: روزی که ظرفیت صفر است، چند مهلت سخت هم‌زمان، فعالیتی که در هیچ بازه‌ای جا نمی‌شود، وقفهٔ سه‌روزه و بازگشت، کلاس ضبط‌شده‌ای که نیمه‌کاره رها شده، تغییر تاریخ آزمون پس از ساخت برنامه، صف بازبینی بزرگ، دو کلاس هم‌پوشان، و مسیر پایگاه داده با نویسه‌های فارسی.

## ۶. تست دستی و میدانی (هنوز انجام‌نشده)

مواردی که خودکارشدنی نیستند و در `KNOWN_LIMITATIONS.md` به‌عنوان **انجام‌نشده** فهرست شده‌اند:

* اجرای EXE روی **ویندوز فیزیکی** ۱۰/۱۱ (اجرای زیر Wine جایگزین کامل نیست).
* آزمون میدانی با ۳ تا ۵ دانش‌آموز واقعی (بازهٔ فاز ۸ نقشهٔ راه).
* آزمون دسترس‌پذیری با صفحه‌خوان واقعی (در حال حاضر فقط برچسب‌ها و ترتیب فوکوس منطقی بررسی می‌شود).
* آزمون چندزبانگی/چندکاربره روی یک دستگاه.

|---|---|---|
| ساخت | `python -m PyInstaller k2.spec --noconfirm` | ✅ انجام شد (زیر Wine با پایتون ویندوز) |
| اجرای EXE | `K2.exe --db <مسیر> --headless` | ✅ انجام شد؛ کد خروج ۰ و پایگاه داده ساخته شد |
| اجرای دوباره روی همان پایگاه داده | همان فرمان | ✅ انجام شد |
| اجرای گرافیکی | `K2.exe` با نمایشگر | ⚠️ زیر Xvfb بررسی شد؛ روی ویندوز واقعی تأیید نشده |
| تست روی ویندوز تمیز بدون پایتون | دستی | ❌ انجام‌نشده |
